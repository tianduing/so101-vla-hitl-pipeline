# 04 逐步修复方案

## 第一步：把“权重来源”变成可验证事实

修改文件：

`sim_mujoco/src/so101_mujoco/adapters/policy_adapter.py`

关键措施：

- 强制从调用者传入的checkpoint加载；
- 不允许配置中的旧基础模型路径覆盖目标checkpoint；
- 计算checkpoint SHA256；
- 抽查`safetensors`真实张量；
- 与内存同名张量逐元素验证；
- 把验证结果写入每次评估JSON。

验收标准：日志必须同时包含请求路径、实际来源、SHA256、探针张量和`verified: true`。

## 第二步：建立可信的闭环基线

不要只算离线MAE。固定：

- 随机seed列表；
- 最大运行时间；
- 动作队列长度；
- 抬升和保持门槛；
- 每个seed的视频和JSONL日志。

权重修复后的单ACT 5/10和SmolVLA 4/10才是可信起点。

## 第三步：只使用物理有效数据

构建器先完整回放动作，只有通过成功检测后才写入数据集。

每条记录保存：

- 源episode；
- 物块XY；
- 帧数；
- 成功帧数；
- 峰值抬升；
- 构建方法。

这样可以防止把“机器人动了但方块没动”的轨迹当成成功示范。

## 第四步：针对空间覆盖补数据

定位稳定失败位置后，不要盲目加训练步数。先计算失败位置与已有成功示范的最近距离，再围绕空洞区域建立小网格。

seed 48、49采用±3 mm、5×5网格，最终得到100条严格成功轨迹。

## 第五步：小步微调并频繁评估

从当前最佳模型继续训练，而不是从头开始：

```text
学习率：2e-6
backbone学习率：8e-7
batch size：1
每100 step保存
```

小步微调的目标是修补局部能力，减少灾难性遗忘。第100 step已经修复难例，因此没有因为“训练越久越好”而强制选择600 step。

## 第六步：专家路由而不是权重平均

权重插值失败后，保留每个完整checkpoint及其归一化统计。路由只用真实相机可获得的RGB绿色中心，不使用仿真特权坐标。

在线逻辑：

```text
特殊难例像素区 -> 难例专家
其余 x < 195 -> 辅专家
其余 -> 主专家
```

## 第七步：严格做未见位置测试

开发位置达到9/10后立即冻结配置，用seed 52–71测试。发现单ACT只有9/20，及时阻止了“模型达到90%”的错误结论。

## 第八步：加入透明的工程恢复器

当纯模型短期无法达到85%时，不伪造模型成绩，而是明确增加第二条控制路径：

```text
初始RGB图像
  -> 绿色中心检测
  -> 像素到桌面XY标定
  -> 最近物理成功示范检索
  -> 动作轨迹执行
```

评估时不读取MuJoCo物块真实坐标。最终20个未见位置成功17次。

## 第九步：单独评估稳定性

抓取、稳定保持、搬运和放置要分成不同指标。增加`--post-success-seconds`后发现3秒保持仅4/10。

这项失败不应删除，而应成为下一阶段“夹稳再搬运”的入口。

## 第十步：保留失败实验

本次有价值的失败包括：

- 权重平均：0/10；
- 交换归一化统计：0/10或接近0；
- 简单慢2倍：6/10；
- 平滑和限幅：4/10；
- 单轨迹网格专家：关键位置0/2；
- 严格稳定保持：4/10。

失败实验告诉下一个维护者哪些方向已经验证无效，避免重复消耗GPU时间。
